We wanted a database client that felt quick. Click a table, see the table. Run a query, get the results. Fairly modest demands, apparently.

What’s in it

Room for your databases
Multiple connections, separate windows. Production gets its own alarming color. More database engines are on the way.
The useful bits
SSH tunnels, schema browsing, SQL tabs, saved queries, and edits you can review before saving.
Less waiting around
Reused connections. Virtualized rows. Work kept off the UI thread. Speed comes from doing less work, which suits us perfectly.
Your monitor gets a say
Built with egui: a native, GPU-rendered UI that can redraw at your monitor’s refresh rate. Smooth scrolling, resizing, and moving around your data. You bought the nice monitor. Might as well use it for something besides the mouse cursor.
No browser included
Rust + egui. You already have a browser. It’s displaying this website.

A few entirely reasonable questions

Is it written in Rust?

Of course it is. We also use mise, and mise is written in Rust. That’s how you know it’s good. Please don’t ask any follow-up questions about this methodology.

Why did we start with PostgreSQL and SQLite?

Because PostgreSQL is the only correct choice for a server-side SQL database, and SQLite is obviously, objectively awesome. These are completely unbiased engineering conclusions.

MySQL, MariaDB, Redis, and more are planned. We can have opinions and still support your toy databases.

Handmade?

Every line, by skilled artisans. Our artisan is called Astra and works suspiciously quickly.

Fine. It’s vibe coded. You can read the source.

Faster than my current client?

That’s the plan. We’re tired of open-source database apps making a small table feel like a large undertaking. We’re testing real queries and fixing the slow bits. A flattering bar chart will have to wait.

Can I use it yet?

If you’re happy building from source and finding rough edges, yes. Packaged releases are still coming. This is early software; we’re using it and working on it.
